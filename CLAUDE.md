## Project Overview

A 3D Tic-Tac-Toe game with a "best of 3" scoring system played on a 3x3x3 cube. The game features glassmorphism UI, animated gradient backgrounds, interactive 3D visualization with Three.js, and 49 possible winning patterns. First player to win 3 rounds becomes the champion.

**Tech Stack:** HTML5, CSS3, vanilla JavaScript (ES6+), and Three.js for 3D rendering - no build tools required.

**Live Demo:** https://krisyupher.github.io/tres-en-linea/

## Architecture Overview

### Core Game State Management
The game uses a simple global state pattern ([script.js](script.js)):
- `board`: 3D array tracking cell states (`[layer][row][col]` with values `"-"`, `"X"`, or `"O"`)
- `currentPlayer`: Toggles between `"X"` and `"O"`
- `winner`: Stores current round winner
- `score`: Object tracking wins (`{ X: 0, O: 0 }`)
- `gameActive`: Boolean controlling whether moves are allowed

### Three.js State
- `scene`: The 3D scene container
- `camera`: PerspectiveCamera positioned at (5, 5, 5)
- `renderer`: WebGLRenderer with alpha and antialiasing
- `controls`: OrbitControls for interactive rotation
- `cubeGroup`: Group containing all 27 cell meshes
- `cellMeshes`: 3D array `[layer][row][col]` storing mesh references
- `raycaster`: For 3D click detection
- `mouse`: 2D vector for mouse position

### Winner Detection System
Winner checking uses pattern matching against 49 possible win patterns generated by `generateWinPatterns()` ([script.js:314-369](script.js#L314-L369)):

**Pattern Breakdown (49 total):**
- 9 horizontal rows (3 per layer × 3 layers)
- 9 vertical columns (3 per layer × 3 layers)
- 6 face diagonals (2 per layer × 3 layers)
- 9 vertical pillars (through layers, z-axis)
- 12 vertical face diagonals (XZ and YZ planes)
- 4 space diagonals (corner to corner through center)

Pattern format: `[[layer, row, col], [layer, row, col], [layer, row, col]]`

When a winner is found, the game:
1. Sets `gameActive = false` to prevent further moves
2. Calls `drawWinnerLine3D()` to animate a 3D tube through the winning cells
3. Updates the score and checks for a champion (3 wins)

### 3D Rendering and Animation System
The 3D scene is rendered continuously at 60fps using `requestAnimationFrame` ([script.js:520-528](script.js#L520-L528)):
- Updates OrbitControls for smooth damping
- Renders the scene with `renderer.render(scene, camera)`

**Winner Line Animation** ([script.js:407-451](script.js#L407-L451)):
- Creates a TubeGeometry connecting start and end cell positions
- Animates opacity from 0 to 0.9 over 500ms
- Uses player-specific colors (pink for X, cyan for O)
- Stored in `scene.userData.winnerLine` for cleanup

**Symbol Appearance Animation** ([script.js:290-311](script.js#L290-L311)):
- Scale animation from 0 to 1 with cubic easing
- 300ms duration with overshoot effect
- Applied to X (crossed cylinders) and O (torus) geometries

### CSS Architecture
The CSS uses a design system with CSS custom properties ([style.css:15-63](style.css#L15-L63)):
- **Player colors:** `--color-player-x` (#ec4899 pink), `--color-player-o` (#06b6d4 cyan)
- **Glassmorphism:** Applied via `backdrop-filter: blur()` with semi-transparent backgrounds
- **Animation tokens:** Transition speeds and shadow values defined as variables

Key animations:
- `gradientShift`: Animates the body background gradient
- `cellPop`: Spring animation when placing X/O marks
- `scoreAppear`: Rotation animation for score marks
- `championPulse`: Breathing effect for champion text

### 3D Interaction System
**Raycasting for Click Detection** ([script.js:148-180](script.js#L148-L180)):
1. Convert mouse position to normalized device coordinates (-1 to 1)
2. Cast ray from camera through mouse position
3. Find intersecting meshes with `raycaster.intersectObjects(cubeGroup.children, true)`
4. Extract `{layer, row, col}` from `mesh.userData`
5. Validate move and update board state

**Hover Effects** ([script.js:190-229](script.js#L190-L229)):
- Highlights empty cells with emissive glow on hover
- Changes cursor to pointer for valid cells
- Resets previous highlight when moving to new cell

### DOM Event Flow
1. Canvas clicks → `handleCanvasClick()` uses raycasting → updates 3D board state → checks winner → switches player
2. "Restart" button → `restartRound()` clears 3D board and removes symbols but preserves scores
3. "Return" button (champion overlay) → `resetGame()` resets everything including scores

### Responsive Behavior
The game uses CSS clamp() for fluid typography and `min()` for grid sizing to work across all devices. The layout switches from horizontal (desktop) to vertical (mobile) at 768px breakpoint.

## 2D Voice Mode (Play vs AI by voice)

A second game mode lives alongside the 3D game and is toggled via the **3D / 2D Voice** buttons (`.mode-btn`). It is implemented entirely in the "2D VOICE MODE" section at the bottom of [script.js](script.js) and is kept independent from the 3D logic (separate `board2D`, `score2D`, `gameActive2D`).

- **Players:** You are `X` (voice or click), the AI is `O` and replies automatically after a short delay.
- **Voice input:** Web Speech API (`SpeechRecognition`/`webkitSpeechRecognition`, `en-US`). The mic button (`#btn-voice`) toggles continuous listening. `parseCell()` maps spoken words to a `{row, col}` using `ROW_WORDS` (top/up, bottom/down), `COL_WORDS` (left/right), and `CENTER_WORDS` (center/middle). Two words pick a cell, e.g. "top center", "middle left", "bottom right"; "center" alone → middle cell. Saying "restart"/"new game" starts a new round.
- **Spoken feedback:** Speech synthesis (`speak()`) announces the AI's move ("I'll take middle center.") and the round/game result ("You're so good, you won!" / "Better luck next time!").
- **AI levels** (`chooseAIMove`): `easy` = random; `medium` = win/block then center > corners > edges (`heuristicMove`); `hard` = full `minimax` (O maximizes). Selected via `.diff-btn` (Initial / Medium / High).
- **Winner detection:** `WIN_LINES_2D` (8 lines) via `winnerOf2D()`/`checkResult2D()`. Reuses the shared score panel and champion overlay (best of 3). Switching modes clears the shared score display and resets the round.

Graceful degradation: if the browser lacks SpeechRecognition the mic button is disabled with a notice; clicking cells still works.

## Important Implementation Details

### 3D Cube Coordinate System
- **Layers (Y-axis):** 0 (bottom), 1 (middle), 2 (top)
- **Rows (Z-axis):** 0 (back), 1 (middle), 2 (front)
- **Columns (X-axis):** 0 (left), 1 (center), 2 (right)
- **Spacing:** 1.0 unit between cells
- **Cell size:** 0.9 units (BoxGeometry)
- **Cube centered at origin:** Offset of -1.0 applied to all axes

### Player Switching
Current player switches only when no winner is detected. This ensures the winning player's color remains active for the 3D winner line animation and UI feedback.

### Champion Detection
When a player reaches 3 wins, a 1-second delay shows the winning line before displaying the champion overlay ([script.js:464-469](script.js#L464-L469)).

### 3D Symbol Creation
- **X:** Two cylinders (0.05 radius, 0.8 height) rotated ±45° on z-axis
- **O:** Torus (0.3 major radius, 0.05 tube radius)
- Both use MeshPhongMaterial with emissive glow matching player colors

### Animation Performance
- Three.js uses WebGL for hardware-accelerated rendering at 60fps
- OrbitControls with damping provides smooth rotation
- Raycasting efficiently detects cell intersections
- CSS animations use `ease-in-out` timing functions for UI elements

## Testing Considerations

When testing changes:
1. Verify all 49 win patterns work correctly across all pattern types:
   - Planar patterns (rows, columns, diagonals on each layer)
   - Vertical pillars (through layers)
   - Vertical face diagonals (XZ and YZ planes)
   - Space diagonals (corner to corner)
2. Test the full game flow: 3 rounds → champion screen → return to fresh game
3. Verify 3D cube rotation works smoothly with OrbitControls
4. Test raycasting accuracy - cells should highlight correctly on hover
5. Check that symbols (X and O) appear correctly at all rotation angles
6. Verify both player colors (pink/cyan) for cells, symbols, and winner lines
7. Test on mobile devices for touch rotation and interaction
8. Verify WebGL support and graceful degradation
9. Test winner line drawing through 3D space for various win patterns
10. Check performance at 60fps during cube rotation and animations
